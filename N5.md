# N5 — Feedback-Aware Line Item Re-extraction

## Status: Planned (not yet implemented)

## Background

The N3/N4 pipeline includes a Line Item Review gate (Step 3 of 4) where the user
reviews the number of line items extracted per zone before the matching pipeline
runs. The UI previously exposed two buttons — **Analyze with AI** and **Re-extract**
— that were removed on 2026-06-08 because both were found to be non-functional:

1. **Analyze with AI** — isolated diagnostic Claude call that returned a read-only
   assessment. Output was never passed downstream to any correction step.

2. **Re-extract** — fired `comparison/n3-line-item-review.completed` with
   `action='reextract'` to resume the existing Inngest function run. Two bugs
   made this non-functional:
   - **Memoization bug**: After `p8-reextract-line-items` completed, all
     downstream steps (p9–p18) returned cached results from the first run
     via Inngest's step history. The re-extracted line items were written to
     `n3_line_items` but never processed through normalization, embeddings,
     candidate generation, scoring, assignment, or adjudication. The final
     comparison output was identical to the pre-re-extract output.
   - **Ignored feedback**: The user's description of what was wrong was sent
     in the event payload (`userFeedback`) but was never passed to the
     extraction prompt. Re-extraction ran the exact same prompts against
     the exact same PDF pages as the original run, producing essentially
     the same (wrong) output.

---

## N5 Design

### Goal

Allow users to describe a specific extraction error at Step 3, trigger a
targeted re-extraction that incorporates their feedback into the extraction
prompt, and have the full downstream pipeline re-run on the corrected data.

---

### Architecture

#### 1. Feedback-aware extraction prompts

The Symbility and Xactimate extraction prompts (and the shared N3 extractor)
must accept an optional `userFeedback` string. When provided, this is injected
into the prompt as additional context, e.g.:

```
The user has reported the following issue with this zone:
"Kitchen is missing approximately 4 line items around pages 8–11."
Focus carefully on those pages and ensure all items are captured.
```

Both `symbilityExtractLineItems` and `xactiExtractLineItems` (and
`extractLineItemsN3`) need a `userFeedback?: string` parameter threaded
through to the prompt builders.

#### 2. Synchronous extraction in the re-extract route

Rather than resuming the existing Inngest pipeline run (which carries
memoized step history), the re-extract API route should:

1. Run `orchestrateExtractLineItems` (or `extractLineItemsN3` for N3)
   **synchronously** within the route handler, passing `userFeedback`.
2. Leave the existing Inngest function run paused at its `waitForEvent`
   gate — it will expire harmlessly at its 24h timeout.
3. Fire a **new** Inngest event: `comparison/rerun-downstream.requested`.

This is the same pattern already used by `zone-correction/route.ts`, which
calls `proposeCorrespondencesN3` synchronously after zone updates.

#### 3. New Inngest function: `process-comparison-downstream`

A lightweight new function triggered by `comparison/rerun-downstream.requested`.

**Input event data:**
```ts
{
  comparisonId: string;
}
```

**Steps (all shared N3 passes, fresh execution context — no prior history):**

| Step ID | Pass |
|---|---|
| `p9-normalize-line-items` | `normalizeLineItemsN3` |
| `p10-extraction-validation` | `validateExtractionN3` |
| `p11-generate-embeddings` | `generateEmbeddingsN3` |
| `p12-generate-candidates` | `generateCandidatesN3` |
| `p13-score-candidates` | `scoreCandidatesN3` |
| `p14-build-components` | `buildComponentsN3` |
| `p15-assign-matches` | `assignMatchesN3` |
| `p16-group-matching` | `groupMatchingN3` |
| `p17-llm-adjudication` | `llmAdjudicationN3` |
| `p18-persist-decisions` | `persistDecisionsN3` |

Because this is a fresh function run, none of these step IDs exist in its
history — all steps execute for real against the freshly re-extracted data.

**Concurrency:** Lock per `comparisonId` to prevent race with the main pipeline.

#### 4. UI (to be designed)

- Remove the "Something looks off" toggle flow from the current step.
- Replace with a single feedback form that collects:
  - Which side(s) to re-extract: Yours / Adjuster / Both
  - Freeform description of what's wrong
- Single **Re-extract** button that submits feedback + triggers the new flow.
- No "Analyze with AI" step — feedback is incorporated directly into the
  extraction prompt. The diagnostic step added latency and user confusion
  without meaningfully improving extraction accuracy.
- After re-extract completes, user is returned to Step 3 to review the
  updated counts before confirming.

### Notes

- The `userFeedback` param is optional — when absent, extraction runs with
  the standard prompt (same behavior as today).
- The existing `p8-5-line-item-review-gate` `waitForEvent` in the main
  pipeline should be updated to only listen for `action='confirm'` so that
  a stale re-extract event cannot accidentally wake a future run. Alternatively,
  stop firing the old event entirely from the re-extract route.
- Extraction at this stage can take 2–5 minutes for large PDFs. The UI should
  show a clear "Re-extracting…" state and poll for status rather than relying
  on a synchronous response.
- Credit cost: re-extraction against both sides should consume the same credit
  as the original extraction. Warn the user before submitting.
- **Page-span chunking** (Symbility + Xactimate extractors): the large-zone
  chunking logic currently splits only zones exceeding `ITEM_SPLIT_THRESHOLD`
  (60 items). Zones with a large page span but low item count (e.g. 8 pages,
  48 items) bypass chunking and are sent as a single oversized Claude call,
  which causes significantly longer extraction times. The classification should
  also split on page span — e.g. `pageSpan > MAX_PAGES_BEFORE_SPLIT` (suggested
  value: 3–4 pages) — so large-page zones are always chunked regardless of
  item count. Affects `lib/n4/extractors/symbility/extract-line-items.ts` and
  `lib/n4/extractors/xactimate/extract-line-items.ts`.
